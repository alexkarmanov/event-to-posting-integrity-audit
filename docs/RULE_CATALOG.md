# Event-to-Posting Integrity Audit — Rule Catalog (R01–R14)

Single source of severity, owner role and review action: `config/rule_catalog.csv` (editable). Status key: **TESTED** = covered by an automated test that currently passes (every listed subtype has at least one test).
Precedence for choosing the *primary* issue in a case (lower wins): R04, R01, R02, R03, R14, R09, R05, R06, R08, R07, R11, R10, R12, R13. Secondary issues stay visible (`primary_case = N`) and are never added to case counts or value totals.

## Severity and priority (transparent and editable)
1. Base severity from `rule_catalog.csv`. 2. Forced tiers where stated above (lag tiers, handoff aging, conflicting IDs). 3. Value escalation for R05–R08 and R12: simulated CAD value ≥ `value_high_cad` → HIGH; ≥ `value_medium_cad` raises LOW to MEDIUM.
`priority_score = 1000 × severity_points (HIGH 3, MEDIUM 2, LOW 1) + min(value_cad, 499) + 10 × min(aging_shifts, 9)`. Rank is dense over primary issues, ties broken by `exception_id`.

## Review actions are proposals
Every action is a *review* step for the named owner role. Root causes are hypotheses. No rule proposes deleting data or adjusting stock to match a count.

## Case families (added after review)
`STOCK_IMPACT` = R05–R09, R12, R13 (may change what the system says is on hand); `TIMING_PROCESS` = R10, R11; `DATA_QUALITY` = R01–R04, R14. The workbook and `Exceptions.csv` carry `case_family`, and the executive summary splits the HIGH count by family so timing and handoff cases are not read as stock losses.

## Simulated CAD value
Computed for R05–R09, R12, R13, R14 only; see `docs/KPI_DEFINITIONS.md` for the quantity valued per rule. Value-based severity escalation applies to R05, R06, R07, R08 and R12.
